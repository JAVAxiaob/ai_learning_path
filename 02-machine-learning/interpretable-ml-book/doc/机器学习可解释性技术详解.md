## 三、三大最常用方法详解 (面试必考!)

### 3.1 ⭐ SHAP Shapley值 (博奕论分配功劳)

```python
import shap
# ---- 初始化 ----
explainer = shap.TreeExplainer(xgb_model)   # 树模型专用! 超高速精确
# explainer = shap.KernelExplainer(model.predict_proba, X_train[:100])  # 通用Kernal版 慢但任何模型
shap_values = explainer.shap_values(X_test)

# ---- 全局可视化 ----
shap.summary_plot(shap_values, X_test, plot_type="bar")   # 条形图: 全局重要性TopN
shap.summary_plot(shap_values, X_test)   # Beeswarm蜂群图! ⭐每点=1样本,颜色=特征值大小,位置=SHAP贡献
# 蜂群图一眼看出: ① "最近6个月交易次数"(红色高值) 正向推高预测概率 ② "逾期次数" 红高值 负向推低

# ---- 局部单样本瀑布图 ----
idx = 123
shap.plots.waterfall(shap_values[idx])   # ⭐客户123为什么被拒贷?
# 输出: 基础值=0.58  → 逾期次数(-0.22) → 月收入低于阈值(-0.11) → ... → 最终预测值0.12(拒贷)
```

> SHAP三大公理(面试背):
> ① **局部准确性 Local Accuracy**: 所有特征SHAP值加起来 = f(x) - E[f(x)] (正确加起来就是预测值减平均值)
> ② **缺失性 Missingness**: 特征xi在模型中没用到 → φ_i=0 (贡献严格0)
> ③ **一致性 Consistency**: 模型改动让某特征边际贡献增加 → SHAP值绝不减少 (公平分配功劳)

### 3.2 Permutation Importance 置换重要性 (最可靠的全局重要性)

```python
from sklearn.inspection import permutation_importance
# ⭐比XGBoost内置.feature_importances_靠谱的多! 内置的基于分裂次数有偏 (高基数特征占便宜)
result = permutation_importance(
    model, X_val, y_val,           # 必须用验证集! 不能用训练集
    scoring="roc_auc", n_repeats=10, random_state=42, n_jobs=-1
)
# 原理: 每次随机打乱一列feature的值,模型AUC下降越多说明这个feature越重要!
# Top5重要性 = importances_mean.argsort()[-5:]
```

> 面试踩坑: **Gini/Gain内置重要性为什么不靠谱？** → 偏向高基数/多取值的特征，哪怕是随机列也会被分到伪重要性。Permutation打乱任何特征公平比较，结果更可靠。

### 3.3 PDP vs ALE 部分依赖图 vs 累积局部效应

| 维度 | PDP (sklearn默认) | ALE (修正版推荐!) |
|-----|------------------|------------------|
| 原理 | 固定所有样本x_s=某值 → 平均预测 | 样本附近区间内做差分, 消除其他特征相关影响 |
| 特征相关时 (如age和income正相关) | ❌严重不准! 用了实际不存在的组合(高年龄+极高收入) | ✅正确,只看相邻样本差分 |
| 计算量 | O(N) | O(N log N) 略慢 |
| 推荐场景 | 特征独立很少相关 (如OneHot后纯独立) | 默认任何场景, 修正PDP系统性偏差 |

## 五、高频面试题 (算法/数据岗半壁江山)

**Q1: SHAP为什么比LIME更靠谱？** (必考题!)
> A: 三大区别 ① **理论保证**: SHAP基于博弈论Shapley值, 有三大公理保证(局部准确/缺失/一致性) 唯一公平分配功劳; LIME局部线性近似没有理论保证 ② **稳定性**: 相同样本相同模型10次跑SHAP结果完全一样; LIME扰动随机 每次结果略有不同 ③**可加性**: 全局加总能得到特征总重要性; LIME局部不能直接加得全局。LIME优点: 通用任何模型不用Tree, 可视化结果更直观给业务方。

**Q2: 信贷风控模型给用户的"拒贷理由"怎么生成？实战步骤？**
> A: 5步标准流程：① 模型推理算预测值 ② SHAP算每个样本每个特征的SHAP值φ_i ③ 取负向贡献TOP3特征 (负贡献最大 = 拉低通过率最多的) ④ 把特征名→业务话术映射字典："overdue_12m" → "您近12个月逾期次数偏多" ⑤ 拼接成自然语言理由 + 合规话术 + 申诉路径。监管要求必须真实反映模型判断，不能瞎编理由。

**Q3: 一个99%准确率的模型上线了效果差，怎么用可解释性工具排查？** (场景题!)
> A: 标准排查清单 (按优先级):
> 1. **Permutation Importance**: 看Top10重要特征中有没有"诡异"的？比如样本ID/hash/日期时间戳占了Top1 → 模型学了泄漏伪特征！
> 2. **SHAP蜂群图**: 有没有特征完全"反常识"？比如"月收入高"红色高值反而在负向区域 → 特征工程漏了对数变换/业务逻辑反了
> 3. **训练/验证特征分布对比**: SHAP训练集vs测试集PDP/ALE，发现某特征训练分布0~1000但线上实际10万 → OOD分布漂移
> 4. **单样本瀑布图抽样**: 抽10个错判Case，看模型到底"看了啥特征判错"，90%的坑是训练集脏标签/重复样本/特征穿越。
