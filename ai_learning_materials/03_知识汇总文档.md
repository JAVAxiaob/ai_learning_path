## 第一部分：核心概念与术语速查

### AI基础概念

| 术语 | 解释 | 与你的关联 |
|------|------|-----------|
| 机器学习 (ML) | 让计算机从数据中学习规律，而非硬编码规则 | 类似训练代码，但"规则"由数据自动得出 |
| 深度学习 (DL) | 使用多层神经网络的机器学习方法 | 主流AI应用（图像/语音/NLP）的基础 |
| 推理 (Inference) | 用训练好的模型预测新数据 | 相当于调用predict()函数，部署阶段的核心操作 |
| 模型 (Model) | 保存训练后参数的文件 | 类似Android的.so库/Java的jar，需加载后使用 |
| TFLite | TensorFlow的轻量化版本 | Android端推理专用框架，安装包大小小 |
| ONNX | 开放神经网络交换格式 | Java/前端/Android通用的模型格式，跨框架部署 |
| LLM | 大语言模型 | ChatGPT/文心一言等，通过API调用或本地部署 |
| Agent | 能自主规划任务的AI系统 | 传统规则引擎的进化版，可动态调用工具/API |
| RAG | 检索增强生成 | LLM + 企业知识库，解决最新信息获取问题 |
| 向量嵌入 (Embedding) | 将文本/图像转为高维向量 | 类似数据库索引，但用于语义相似度搜索 |
| 向量数据库 | 存储和检索向量的数据库 | 类比Redis/MySQL，但专用于Embedding |

### 工程化概念

| 术语 | 解释 | 与你的关联 |
|------|------|-----------|
| MLOps | 机器学习运维 | DevOps在AI场景的延伸，CI/CD、监控告警方式类似 |
| 模型版本管理 | 管理不同版本的模型文件 | 类比Git管理代码，但管理的是模型文件 |
| 数据漂移 | 线上数据分布与训练数据不一致 | 类比软件的"环境依赖变化"，需监控 |
| 模型服务化 | 把推理封装为API | 类比传统微服务，但服务的是模型推理 |
| 模型压缩 | 减少模型大小/计算量 | 类比代码混淆/压缩，但目的是提升推理速度 |
| 量化 (Quantization) | float32 → int8 | 减少模型体积75%，速度提升2-4倍（Android端必备） |
| 剪枝 (Pruning) | 删除冗余权重/神经元 | 类比代码删除Dead Code，损失小精度换大加速 |
| 知识蒸馏 | 用大模型教小模型 | 类比"架构师指导初级工程师"，小模型获得接近大模型的能力 |

## 第二部分：技术迁移图谱

### 1. 传统Android开发 → 端侧AI开发

| 传统技能 | 如何应用到AI场景 | AI新知识 |
|----------|-----------------|---------|
| 相机开发 (CameraX/Camera2) | 捕获图像帧 → 输入模型 | 图像预处理Pipeline (resize/normalize) |
| NDK / JNI调用 | 调用C++编译的TFLite/ONNX库 | TFLite C API、模型文件管理 |
| 性能优化 | 推理延迟分析、内存占用 | GPU代理(Delegate)、NNAPI加速 |
| 传感器数据 | IMU/GPS数据作为模型输入 | 时间序列数据格式、归一化 |
| 离线存储 (Room/SQLite) | 缓存推理结果、模型元数据 | 向量相似度搜索（可选） |
| 网络编程 (OkHttp/Retrofit) | 端云协同推理 | 流式推理结果、模型热更新 |
| 权限管理 | CAMERA、INTERNET权限申请 | 与传统一致，无新知识点 |
| 打包优化 (ProGuard/R8) | 模型文件放在assets | 模型AAB动态分发、按需下载 |

**核心技能迁移公式**:
``
端侧AI开发 = Android基础开发 + TFLite/ML Kit API + 图像/传感器数据预处理
``

## 第五部分：从传统开发到AI开发的关键心态调整

### 1. 从"确定性"到"概率性"
- **传统开发**: if-else逻辑，输出完全确定
- **AI开发**: 模型给出置信度，可能出错，需容错设计
- **调整建议**: 永远设计兜底方案、设置置信度阈值、AB测试验证效果

### 2. 从"代码驱动"到"数据驱动"
- **传统开发**: 代码逻辑决定输出
- **AI开发**: 训练数据质量决定输出上限
- **调整建议**: 投入时间在数据清洗/标注，而非只调模型参数

### 3. 从"完全控制"到"黑盒调用"
- **传统开发**: 每一行代码执行路径可控
- **AI开发**: 神经网络内部行为难以解释
- **调整建议**: 接受黑盒属性，关注输入输出关系、异常样本收集、指标监控

### 4. 从"写测试用例"到"建评估数据集"
- **传统开发**: Unit Test / Integration Test
- **AI开发**: 构建golden test set，持续评估模型精度/召回率
- **调整建议**: 把评估数据集视为核心资产，和代码同等重要
