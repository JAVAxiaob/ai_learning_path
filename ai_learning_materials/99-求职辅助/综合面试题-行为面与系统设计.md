## 第一部分：行为面试 STAR 答法（8道高频题 + 逐字模板）

行为面试 = 看你**软实力**。技术过关但行为面差，50%的概率会挂（团队协作/抗压/成长潜力 = 一票否决）。

### ✅ 核心方法论：每道行为题，**严格按 STAR 模板 + 最后加"反思改进"** = 加分

```
S (Situation) 背景：2句话，当时遇到什么问题/场景（给数字）
T (Task)   任务：我的职责是什么（"我主导XX"而不是"我们做XX"）
A (Action) 行动：⭐ 你具体做了哪3-5个动作（占回答50%篇幅！）
R (Result) 结果：⭐ 量化数字结果（成本/时间/效率/指标）
+ ⭐ 【复盘改进】加分项：如果重来，我会怎么做？学到了什么？
```

### 题3：你遇到过的最大技术挑战 / 最大困难是什么，怎么解决的？

#### 选 AI 相关的挑战答（别再答 5 年前的 Maven 依赖冲突了）：
> **S + T**：RAG 系统上线第一周，有客户反馈 10% 的问题答案都是错的（幻觉），但是我们离线评估明明是 92% 的 Faithfulness，我花了 2 天定位原因。
>
> **A**：① 先把所有 badcase 收集回来，发现**有 7 成是 chunk 切分问题**：原文跨段落的长答案被切成了两块，每块单独检索都拿不全；② 剩下 3 成是 **Lost in the Middle 问题**：最相关的文档被排在 3/4 名，LLM 注意力只看头尾中间全忘了；③ 针对性改：chunk 从固定 500 字符改 **SentenceWindow 3 句语义切块 + 120 overlap**；检索加 **LongContextReorder 重排头尾相关文档**；④ 再加 CrossEncoder Reranker 从 Top50 精排到 Top4。
>
> **R**：改完上线第二周，**用户反馈错误率从 10% → 1.1%**，满意度从 3.6 分回到 4.8 分。这次踩坑的经验后来整理成了公司内部 RAG 最佳实践文档。
>
> ⭐ 【复盘】最大的收获是：**RAG 不是 "切块 + 向量检索" 就完事了，切分策略 > 检索 > LLM 选型**，很多人上来就换更大的模型，其实 80% 的问题在前两个环节就能解决。

### 题5：给你一个陌生技术（比如 LlamaIndex / MLflow），怎么一周内上手？

#### 高分方法论 = 费曼学习法 + 项目驱动：
> 我有固定的 5 步上手法，亲测有效（拿我 2 周上手 Spring AI 举例）：
>
> **Day 1 信息搜集**：先读**官方文档首页 + QuickStart + FAQ**，再找 3 篇高质量博客/视频（不超过 5 篇），重点看它解决什么问题、核心抽象、生态位；同时找 2 个 GitHub 上的 demo 先跑起来（1小时内要有"Hello World"正向反馈）。
>
> **Day 2 核心概念 + 架构图**：拿一张 A4 纸画它的**核心组件关系图 + 数据流图**（输入→处理→输出）。比如 Spring AI 我就画了：ChatClient → ChatModel抽象 → VectorStore → Document → Translator。图画明白了就说明理解了80%。
>
> **Day 3-4 动手做最小可用项目 MVP**：不是跟着抄教程，而是自己给自己提一个小需求（比如把我的 PDF 简历做成 RAG 能问答），过程中肯定会踩坑，查源码 + 调 Bug = 真正理解的过程。
>
> **Day 5 读一个核心模块源码**：比如 Spring AI 的 Prompt 组装 + Qdrant 相似性搜索实现，理解它为什么这么设计、边界条件怎么处理。
>
> **Day 5 晚上 输出驱动**：写一篇技术博客《xxx 快速入门 + 踩坑 5 条》，**讲不清楚的地方就是我还没完全懂的地方**，回去补。
>
> 这样 5 天下来，一周内绝对可以在生产项目里小范围用了，遇到问题也知道去哪里查。

### 题6：⭐ AI工程师 vs 传统软件工程师，你认为最大的区别是什么？（判断你理解深度）

#### 高分回答 = 3 个维度对比（体现你的深度思考）
> 核心区别一句话：**传统软件工程是构建「确定性系统」，AI 工程是构建「概率性系统」**。在三个维度有本质区别：
>
| 维度 | 传统软件工程（如写订单系统） | AI 应用工程（如做 RAG 系统） |
|-----|------------------------|------------------------|
| **系统行为** | 100% 可复现，同样输入同样输出 → 代码写对了 Bug 就修好了 | **概率性！** 同输入两次答案可能不一样，会有幻觉 → 不能靠"修 Bug"解决，要靠评估+数据+迭代 |
| **质量保证** | 单元测试 + E2E 测试，覆盖率 80%+，全自动化 | 要过 3 关：**离线 Golden 集评估 → A/B 分桶实验 → 线上人工抽检**，100% 自动不可能，要引入人工+指标驱动 |
| **工作内容占比** | 70% 写代码 + 20% 测试 + 10% 运维 | ⭐ 反过来了！**20% 写框架代码 + 50% 数据处理/评估迭代 + 30% 监控/重训练/指标分析**，更多的是"和数据+指标打交道"而非纯写逻辑 |
>
> 结合点：AI 工程 100% 需要扎实的软件工程底子（模块化、可测试、部署、监控），你不能代码写一团糟就做AI；但区别是多了**数据+模型**的两个维度要管理。我之前 5 年的分布式工程底子（高可用/性能调优/灰度发布）都是 AI 工程的基础，我现在补的就是数据和评估迭代的思维。

## 第二部分：AI 系统设计面试 3 道压轴题（大厂 3 面 + 高级岗必出）

### 题 9：⭐⭐⭐⭐⭐ 设计一个企业级 RAG 问答平台（最常考！没有之一）

#### 答题框架 = 4 步（先问需求再设计，别上来就画图）

**Step 1：需求澄清（说 3 句话，面试官立刻觉得你是老手）**
> 设计前我先确认3个关键需求避免方向错：
> ① **数据端**：支持什么文档格式？(PDF/Word/Markdown/表格?) 更新频率？(实时/小时级/天级?) 要不要权限控制？(A部门不能看B部门文档)
> ② **用户端**：DAU 大概多少？高峰 QPS 多少？P95 延迟目标？（1s / 3s / 10s？） 要不要溯源引用？
> ③ **LLM 端**：只用云端 API 还是混合本地开源模型？预算多少？(单月Token成本上限)

**Step 2：总体架构图（画 5 个模块）**
```
┌──────────────────────────────────────────────────────────────┐
│                         用户端                                 │
│  Web(Vue SSE流式) / App / 企业API（WebHook）/ 飞书/企微机器人  │

│  ┌──────────┐  ┌──────────────┐  ┌───────────────────────┐    │

```

**Step 3：核心模块深入（挑 2 个讲亮点让面试官印象深刻）**
> ① **权限控制**：向量库里每一条向量都带 `dept_ids` 元数据标量字段，用户搜索时带自己部门做**标量过滤**，保证 A 部门绝对搜不到 B 部门文档（Milvus/Qdrant 原生支持 Expression Filter）
>
> ② **成本控制 3 板斧**：第一做 Query Router（LLM 判 3 类：FAQ 直接查缓存不调 LLM / 文档检索走小模型 7B / 复杂推理走大模型 70B）；第二做**语义缓存**，Redis 存问题 Embedding，相似度>0.97直接返回上次答案，实测命中率 30-60%；第三**本地小模型重排+精排**替代远程大模型，Token 用量 -80%
>
> ③ **反馈闭环**：用户每次的点赞/点踩 + 追问 + 修改答案，沉淀成 Golden 数据集，每周自动跑 Airflow：用新数据重新评估 RAGAS 指标，如果 Faithfulness 下降超过 5% → 告警 + 触发索引重建（换 chunk/embedding/精排模型）

**Step 4：可扩展性 + 容灾（最后收尾加分）**
> - 可扩展：所有组件无状态，K8s HPA 按 QPS + GPU 利用率自动扩缩
> - 降级：主 LLM 供应商挂 → 自动 100% 切备用供应商 + 熔断；向量库挂 → 降级为关键词 ElasticSearch 搜索，功能降级但服务不挂
> - 数据一致性：索引写 PostgreSQL 元数据 + 向量库"双写"，每小时对账脚本查差异，自动补漏重建缺失向量

### 题 10：设计一个高并发 LLM 推理服务网关

**核心考点**：多供应商容错 + 成本优化 + 限流 + 监控。简化版 4 板斧：

1. **多供应商适配层**：抽象 `LLMProvider` 接口（OpenAI/Anthropic/国产/本地vLLM），每个供应商是实现类；路由支持按权重分流（80%国产/20%备用）、按模型能力路由（便宜的做分类、贵的做推理）、故障 5xx 熔断 30 秒自动切备用
2. **成本优化 3 招**：请求级缓存（同样 prompt 命中直接返回）、**输入 prompt 压缩**（LLMLingua 压缩上下文 -60%Token）、批量推理（100ms 窗口内请求打包成一批送模型，GPU 利用率从 30%→80%）
3. **两层限流**：用户级 Token Bucket（个人免费用户 10 次/分钟）+ 供应商级并发上限（避免超 OpenAI 每分钟 TPM）
4. **全链路监控 + 计量**：每个请求记日志：`用户ID / 模型 / 输入Token数 / 输出Token数 / 延迟 / 供应商 / 费用`；月底出报表按部门/按用户分账算成本

**核心模式：简单任务端侧本地秒回，复杂任务云端兜底** = 体验最好 + 成本最低

## ✅ 最后：行为面 + 系统设计的 3 条高分铁律

1. **先结构化再展开**：任何题先说"我从3个方面回答这个问题：① XXX ② XXX ③ XXX"，再每部分展开。面试官听 10 个人已经累了，结构清晰 = 分数高 20%
2. **数字 + 对比 = 印象深刻**："延迟降低了很多" → "P95 延迟 4.2s → 650ms，降低了 84%"
3. **"我"做的动作 > "我们"做的成果**：永远说"我主导/我设计/我写了核心模块"，别让面试官追问"所以你具体做了什么？"
