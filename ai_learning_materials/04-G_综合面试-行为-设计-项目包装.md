# 04-G - 综合面试题库: 行为面试 + 系统设计 + 简历项目 (20题)

> 核心: 软实力 + 系统设计能力 + 项目包装, 这是3年经验工程师的核心价值

---

## 第一部分: 行为面试题 (8题)

**1. 自我介绍 (3分钟版本)**

推荐结构:
1. 基本信息: 姓名/学历/工作年限(3年)/当前公司和职位
2. 技术栈概览: 主要技术 + 对应年限 (Android 2年, Java后端 1.5年, Vue前端 1年)
3. AI相关能力: 你已掌握的AI知识 + 可迁移技能 + 做过的AI相关尝试 (即使是自学项目)
4. 职业目标: 为什么转AI方向, 你带来什么差异化价值 (传统工程+AI的结合)
5. 个人特色: 如GitHub星标项目/技术博客/开源贡献/学习习惯

要点:
- 控制在3分钟内 (面试官不会听你长篇大论)
- 用数据说话: 我优化了XX系统, 性能提升Y%, 节省Z成本
- 暗示你是能快速学习的人: 提到自学完成的项目/课程
- 给面试官留钩子: 你提到的每个亮点, 都应该是你有深度内容可以展开的

**2. 你最有成就感的项目是什么**

STAR回答框架:
- Situation: 背景和问题 (如现有的推荐系统效果差, 日活下降15%)
- Task: 你的职责 (我负责重构推荐算法, 引入轻量级特征工程)
- Action: 具体做了什么 (用TFLite实现端侧排序模型, 线上A/B测试验证...)
- Result: 量化结果 (点击率提升32%, 用户停留时间增加18%, 服务器成本降低25%)

加分项:
- 遇到了什么挑战, 如何解决的
- 你从中学到了什么, 下次会如何改进
- 你的工作给团队/公司带来了什么长期价值

**3. 你遇到过的最大技术挑战是什么, 如何解决的**

推荐讲AI相关的挑战, 即使是学习中遇到的:
- 示例1: 模型推理延迟不达标, 尝试了量化/剪枝/多线程, 最终从200ms降到50ms
- 示例2: 端侧模型在不同设备上表现差异大, 建立了设备分级策略
- 示例3: 模型精度不够, 分析了错误样本分布, 针对性补充训练数据

回答要点:
- 先说明问题本质是什么 (不是症状, 而是根因)
- 你尝试了哪些方案, 效果如何, 为什么
- 最终方案的选择依据是什么 (权衡了哪些因素)
- 结果量化, 以及带来的技术/业务价值

**4. 为什么想从传统开发转向AI方向**

回答原则: 不说传统开发不好, 只说AI方向更好

推荐内容:
- 趋势判断: 我观察到AI正在改变软件开发方式, 未来每一个产品都需要与AI能力结合
- 个人兴趣: 我喜欢用技术解决复杂问题, AI让我能做以前做不到的事情 (如从图片生成UI代码)
- 技术积累: 我已有XX年Java/Android/Vue经验, 相信我的工程背景 + AI知识能创造独特价值
- 长期规划: 我计划在AI方向深耕X年, 成为某一领域(如端侧AI/LLM应用)的专家

避免踩雷:
- 不要说传统开发没前途/想赚更多钱 (显得你只看重短期利益)
- 不要说工作太无聊 (暗示你容易厌倦)
- 不要夸大自己AI水平 (诚实说明自己是初级但进步快, 有扎实工程背景)

**5. 给你一个陌生的技术, 你如何在一周内上手并产出**

推荐方法论:
1. 信息搜集(1天): 读官方文档+3篇高质量教程+找2个可运行的demo
2. 概念验证(1-2天): 跑通hello world, 修改关键参数, 观察输出变化
3. 核心概念(1-2天): 读核心原理, 画架构图/流程图, 理解数据如何流动
4. 小型项目(2-3天): 实现一个功能完整的最小产品, 遇到问题查源码+调试
5. 产出总结(半天): 写一篇技术总结/博客, 把学到的东西讲清楚

强调你已验证有效的学习方法 (可用你实际学习某技术的经历举例)

**6. 如何看待AI工程师和传统软件工程师的区别**

核心观点: 软件工程师是确定性系统的构建者, AI工程师是概率系统的构建者

传统软件工程:
- 输入 -> 确定性逻辑 -> 预期输出 (如果程序正确, 100%可预测)
- 质量保障: 单元测试 + 集成测试 + E2E测试 (可自动化)
- 可解释性: 每个分支/函数的行为都是可追踪的

AI工程:
- 输入 -> 统计模型/神经网络 -> 概率性输出 (可能出错, 需要持续监控)
- 质量保障: 验证集/测试集指标 + 线上A/B测试 + 人工抽查 (数据驱动)
- 可解释性: 内部工作原理难以完全理解, 需要从行为层面评估

结合处:
- AI工程师仍需扎实的软件工程能力 (模块化/测试/部署/监控)
- 区别在于多了数据和模型的维度 (数据质量/模型版本/特征管理)
- 你的优势: 已有3年软件工程经验, 现在只需要补上数据和模型维度

**7. 如果给你三个月时间, 你会如何系统性提升自己的AI能力**

推荐规划:
- 第1个月: 基础打牢 (线性代数/概率论/ML基础 + 1个简单项目)
- 第2个月: 深度学习实战 (PyTorch + CNN/RNN + 3-5个Kaggle级别的项目)
- 第3个月: 工程化和方向深入 (部署/监控/LLM应用 + 选定1个方向深挖)

学习策略:
- 做中学: 每学一个知识点, 至少做1个小型应用
- 输出驱动: 写技术博客/做开源项目/分享给他人
- 刻意练习: 做Kaggle比赛, 对比top方案的差距
- 体系化: 不只是看零散文章, 系统学习课程/书籍

**8. 你最想加入什么样的团队, 为什么**

回答要点:
- 文化: 有技术氛围/重视学习/鼓励创新/接受试错
- 业务: AI真正创造业务价值 (不是为了AI而AI)
- 团队: 有资深工程师可以学习, 同事技术过硬又乐于分享
- 产品: 我能参与产品从0到1的过程, 看到自己的工作对用户的影响
- 个人成长: 有清晰的成长路径, 不只是做执行, 也能参与决策

## 第二部分: 系统设计题 (6题)

**9. 设计一个高并发的LLM API网关**

核心功能:
- 多供应商适配: OpenAI/Anthropic/国产模型/本地模型 统一接口
- 流量控制: 按租户/用户维度限流, 按供应商配额调度
- 成本优化: 结果缓存 + 请求合并 + 模型路由 + 失败重试
- 安全审计: 输入输出日志 + 内容安全检测 + 访问控制
- 监控统计: token消耗/延迟分布/错误率/成本统计

关键设计:
- 异步架构: 请求队列 + Worker线程池, 支持排队和取消
- 插件机制: Logging/Auth/RateLimit/ContentSafety 均通过拦截器实现
- 可扩展性: 新增一个LLM供应商只需要实现一个Provider接口

**10. 设计一个端云结合的AI助理App**

架构设计:
- Android/iOS端: 本地小模型做即时响应 + 流式渲染云端大模型结果
- Java后端: LLM接入 + RAG检索 + Agent工具调用 + 对话管理
- Vue管理端: Prompt调试/知识库管理/对话日志查看/用户管理

核心流程:
1. 用户语音/文本输入 -> 端侧意图识别(离线可用)
2. 识别为简单任务: 本地直接完成 (如打开App/设闹钟)
3. 识别为复杂任务: 上传到云端 -> LLM + 工具调用 + 知识库检索
4. 流式返回结果 -> 端侧实时渲染 + 语音合成(TTS)
5. 用户反馈(点赞/点踩/修正) -> 回流用于模型优化

**11. 设计一个可扩展的RAG(检索增强生成)平台**

模块划分:
- 文档处理管线: 上传/解析(PDF/Word/HTML/Markdown) -> 清洗 -> 分块(chunking)
- 向量化服务: 支持多种Embedding模型, 缓存向量, 批量处理
- 向量数据库: 支持多种索引类型, 元数据过滤, 混合检索(BM25+向量)
- 检索服务: 多路召回 + 重排序 + 结果合并 + 质量评分
- 生成服务: 多LLM供应商 + Prompt模板管理 + 输出校验 + 流式响应
- 评估服务: 检索质量评估 + 生成质量评估 + 业务A/B测试

数据流向:
- 文档 chunk -> Embedding向量 -> 存入向量数据库 + 原始内容存关系数据库
- 查询 -> 多路检索(向量+关键词) -> 重排序 -> 拼装成Prompt -> LLM生成
- 用户反馈 -> 标注数据 -> 用于检索/生成的优化迭代

**12. 设计一个AI能力插件市场 (类似ChatGPT Plugins)**

核心概念:
- Plugin: 包含名称/描述/能力声明/API地址/鉴权方式的元数据
- Tool: Plugin对外暴露的可调用函数 (LLM可以选择使用)
- Sandbox: 隔离的执行环境, 限制插件的权限和资源消耗
- Router: 解析用户请求, 选择合适的插件, 编排调用流程

安全设计:
- 插件能力声明必须在白名单内, 不允许超出声明范围的操作
- 用户授权: 每个插件首次使用需用户确认权限
- 调用审计: 所有插件调用都有日志, 可追溯
- 资源隔离: 每个插件有独立的调用额度/超时限制

**13. 设计一个图像搜索系统 (以图搜图)**

核心模块:
- 特征提取: ResNet/CLIP/ViT提取图像特征向量 (可缓存以降低成本)
- 向量索引: FAISS/Milvus 建立ANN索引, 支持亿级图像快速检索
- 排序融合: 向量相似度 + 图像质量分 + 热度/时间加权
- 用户反馈: 不感兴趣/收藏/点击 信号用于重排序模型训练

性能优化:
- 特征提取异步化: 上传后立即返回, 后台异步提取特征
- 多级缓存: 相同/相似图像的特征缓存 + 热门搜索结果缓存
- 分库分表: 按图像特征哈希分段, 水平扩展

**14. 设计一个推荐系统的完整技术方案**

三层架构:
- 召回层 (Recall): 从百万级候选中快速选出几百个 (多路召回: 协同过滤/热门/内容相似/用户画像)
- 粗排层 (Ranking 1): 轻量级模型, 对几百个候选打分排序 (速度优先)
- 精排层 (Ranking 2): 复杂模型(深度神经网络), 对前几十个候选精细排序 (质量优先)

补充模块:
- 重排序/多样化: 避免结果同质化, 平衡探索和利用
- 特征工程: 实时特征(用户行为) + 离线特征(用户画像/物品画像)
- 在线学习: 行为反馈 -> 模型增量训练 -> 快速更新排序模型
- 实验平台: A/B测试框架 + 效果评估 + 自动报告

## 第三部分: 简历项目包装题 (6题)

**15. 如何让传统Android项目体现AI元素**

包装思路:
- 相机应用: 加入实时物体检测 (TFLite) + 智能场景识别 -> 自动优化拍摄参数
- 笔记应用: 图像OCR提取文字 -> 语义搜索笔记 + AI摘要生成
- 日程应用: 从邮件/消息自动提取日程 -> 智能提醒 + 最优路径规划
- 电商应用: 端侧商品推荐 + 图像搜索 (以图搜商品)
- 健康应用: 传感器数据分析 -> 异常检测 + 健康建议生成

**16. 如何让Java后端项目体现AI元素**

包装思路:
- 搜索服务: 关键词匹配 -> 向量检索 + 同义词扩展 + 查询意图识别
- 推荐服务: 基于规则 -> 基于模型 (协同过滤 + LR/DNN排序)
- 风控服务: 规则引擎 -> 异常检测 + 图神经网络识别欺诈模式
- 客服系统: 纯人工 -> LLM自动回复 + 人工接管 + 知识库检索
- 内容审核: 关键词过滤 -> 图像/文本多模态AI审核

**17. 如何让Vue前端项目体现AI元素**

包装思路:
- 表单输入: AI智能补全 + 输入内容自动分类/打标签
- 数据可视化: 自动发现数据异常 -> 生成自然语言分析报告
- 编辑器: 智能纠错 + 风格统一 + 文本摘要 + 翻译辅助
- 设计工具: 草图 -> 标准UI组件 + 风格迁移 + 多主题自动生成
- 搜索: 自然语言查询 -> 结构化检索条件 + 结果智能排序

**18. 设计一个个人作品集AI项目**

项目建议 (任选1-2个深入):
1. 智能简历生成器: 输入基本信息 -> LLM生成专业简历 + 多语言版本 + 岗位定制
2. AI代码助手: 本地IDE插件, 代码补全 + 代码解释 + 自动生成单元测试
3. 个人知识库RAG: Markdown/PDF作为知识库 -> 可以对话问答 + 语义搜索
4. 图像生成工具箱: Stable Diffusion封装 + 多种风格预设 + 批量处理

项目标准:
- 完整: 从前端到后端到部署, 全栈贯通
- 可用: 不是玩具demo, 而是自己会日常使用的工具
- 开源: 代码放到GitHub, 写清晰的README和架构说明
- 文档: 写几篇技术博客, 讲解关键实现细节和踩坑经验

**19. GitHub项目如何写才能吸引面试官**

README结构:
1. 项目简介: 一句话说明这个项目解决了什么问题, 为什么值得存在
2. 功能特性: bullet point列出主要功能, 用GIF/截图展示效果
3. 技术选型: 列出用了哪些技术栈, 以及为什么选择它们 (体现你的技术判断力)
4. 架构设计: 配一张架构图/流程图, 讲解系统如何工作 (数据从哪里来, 经过哪些处理, 到哪里去)
5. 快速开始: 一步一步的命令让用户能在3分钟内跑起来
6. 核心代码片段: 挑1-2个最有技术含量的函数/类做深入讲解
7. 遇到的挑战和解决方案: 展示你分析和解决问题的能力
8. 后续规划: 列出计划实现的功能 (体现你的思考深度)

加分项:
- 有在线demo, 面试官可以直接体验
- 有单元测试, 代码质量有保障
- 有性能测试, 有具体的性能数据和优化记录
- 有架构图/流程图 (比文字更好理解)
- README中有可以复制的curl命令/示例输入

**20. 面试时如何讲清楚一个技术项目 (5分钟版本)**

推荐讲解结构:
1. 背景: 这个项目是做什么的, 解决什么用户痛点 (30秒)
2. 规模: 多少DAU/多少QPS/多少数据量, 用了多少台服务器 (量化价值) (30秒)
3. 架构: 画一张架构图, 讲解数据流向和关键模块 (1分钟)
4. 我的贡献: 具体我负责了哪部分, 遇到什么挑战, 如何解决 (1.5分钟)
5. 技术亮点: 这个项目最值得骄傲的技术点是什么 (1分钟)
6. 结果: 量化结果 + 学到的经验 + 如果重来会有什么改进 (30秒)

关键要点:
- 每个点都要有量化数据 (提升X%, 降低Y毫秒, 节省Z元)
- 讲你做的, 不是团队做的 (用我做了XX, 不是我们做了XX)
- 讲为什么这么做, 以及考虑过什么其他方案 (体现你的技术深度)
- 主动暴露项目的不足和改进方向 (体现你的成熟度和反思能力)

> 本部分是最容易被忽略但最有价值的内容。技术能力是基础, 但面试胜出往往靠:
> 1. 出色的表达和故事讲述能力 (让面试官听懂并记住你的项目)
> 2. 系统设计思维 (不是只会写代码, 而是能设计系统)
> 3. 清晰的职业规划 (知道自己要去哪里, 为什么适合这个岗位)
> 4. 与岗位的匹配度 (让面试官相信你就是他们要找的人)
> 5. 软实力 (沟通/协作/学习能力/抗压性)
