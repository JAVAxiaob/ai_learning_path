## 一、核心AI概念速查（必考基础）

| 术语 | 一句话解释 | 通俗类比 | 面试关联点 🔥 |
|------|----------|---------|-------------|
| **机器学习 (ML)** | 让机器从数据中自动学规律，不用人工写死if-else | 原来人工写规则=给鱼吃；ML=教鱼自己捕食 | 与传统编程的区别：概率输出+数据驱动 |
| **深度学习 (DL)** | 用多层神经网络的机器学习，能学更复杂的模式 | 人脑有很多层神经元，DL模拟这个 | 为什么现在火了？数据+算力两个条件成熟 |
| **训练 (Training)** | 用数据+反向传播更新模型参数的过程 | 学生做练习题+对答案改自己的知识点 | 训练集/验证集/测试集三者区别 |
| **推理 (Inference)** | 用训练好的模型预测新数据，只有前向传播 | 学生上考场做题，不学新知识只输出 | ☕📱 部署阶段核心：延迟/吞吐/成本 |
| **模型 (Model)** | 存了权重参数的文件，加载后可做预测 | 📱相当于.apk/☕.jar文件，要安装才能用 | 格式：.pth/.onnx/.tflite/.gguf区别 |
| **过拟合 (Overfit)** | 训练集表现好→测试集效果差，死记硬背了 | 学生只背了练习题答案，换题就不会 | 解决方法：L2正则/Dropout/数据增强/早停 |
| **欠拟合 (Underfit)** | 训练集和测试集都差，模型太简单 | 学生基础太差，连练习题都不会 | 增加模型复杂度/加特征/训练更久 |
| **偏差-方差权衡** | 偏差=准不准(欠拟合) 方差=稳不稳(过拟合) | 打靶：偏=整体偏左/右 方差=特别散 | 为什么需要权衡？模型复杂度U型曲线 |
| **反向传播** | 链式法则从输出倒算每层权重的梯度 | 考试错题→反推哪个知识点没掌握→改它 | 为什么要存中间激活值？算梯度要用 |
| **梯度下降** | 沿着损失减小最快的方向更新参数 | 下山：找最陡的方向迈小步 | SGD/Momentum/Adam的区别和优缺点 |

## 二、模型部署与性能优化术语（☕📱 必考）

| 术语 | 核心解释 | 面试点 🔥 |
|------|---------|----------|
| 🔥 **ONNX** | 开放神经网络交换格式：PyTorch/TF/任何框架训练完 → 转.onnx → 任何语言/硬件统一跑 | ☕ Java/Android/前端通吃格式，怎么导出+动态轴 |
| 🔥 **TFLite** | TensorFlow的端侧轻量化版本：模型小+依赖小+速度快 | 📱 Android端首选：Delegate选择表 |
| **NCNN / MNN** | 腾讯/阿里开源的端侧推理框架：比TFLite更快+包更小 | 📱 国内环境/GPU极致性能场景选 |
| 🔥 **量化 (Quantization)** | float32 → int8/fp16：模型小2~4倍+推理快2~4倍，精度损失极小 | PTQ训练后量化 vs QAT感知量化区别 |
| **剪枝 (Pruning)** | 删掉模型里冗余的权重/通道，精度降1%模型小2倍 | 结构化(剪通道) vs 非结构化(剪单个权重) |
| **蒸馏 (Distillation)** | 大模型(Teacher)教小模型(Student)，小模型获得大模型80%能力 | 软标签/温度T参数作用 |
| **算子融合 (Operator Fusion)** | Conv+BN+ReLU 合成一个算子，省中间内存 | ncnn/tflite optimize工具自动做 |
| **Delegate / 委托** | 模型算子交给不同硬件加速：CPU→GPU/NPU/DSP | 📱 4种Delegate：XNNPACK/GPU/NNAPI/Hexagon 对比 |
| 🔥 **Batch / 批处理** | 一次送多个样本给模型算，填满GPU算力 | ☕📱 vLLM Continuous Batching为什么吞吐×5？ |
| **吞吐 (Throughput)** | 每秒处理请求数 QPS/Tokens/s | 影响因素：Batch/量化/模型大小 |
| **延迟 (Latency)** | 单个请求从进到出的耗时 P50/P95/P99 | 吞吐和延迟权衡：BATCH大吞吐高但延迟高 |

## 三、大模型 LLM 术语大全（🚀 2025面试重点）

| 术语 | 核心解释 | 面试关联 🔥 |
|------|---------|------------|
| 🔥 **Embedding / 向量嵌入** | 把文本/图像转成高维向量（如768维），向量距离=语义相似度 | RAG基础：向量索引/相似度计算 |
| 🔥 **RAG 检索增强生成** | LLM + 向量检索：先从知识库搜相关文档→拼到Prompt→让LLM看资料回答 | RAG 7步：切块→向量化→存储→查询→重排→组装→生成 |
| 🔥 **向量数据库** | 专门存向量+做相似度搜索的数据库：Chroma/FAISS/Milvus/Qdrant/pgvector | ANN近似搜索/HNSW索引原理 |
| 🔥 **Agent 智能体** | LLM+工具调用循环：思考→选工具→执行观察→...→最终答案 | ReAct模式/工具参数校验/死循环防护 |
| **Tool Calling / Function Calling** | LLM不是生成文字，而是生成JSON格式的工具调用参数 | Pydantic Schema校验/重试机制 |
| 🔥 **Transformer** | 2017年Attention Is All You Need提出的架构，所有LLM基础 | QKV注意力公式/为什么除√d_k/多头/残差 |
| **Attention 注意力机制** | 让模型每个位置能"看到"其他位置，并分配不同注意力权重 | Self-Attention vs Cross-Attention |
| **KV Cache** | 推理时缓存已算过的Key/Value，不用每生成一个token从头算 | 显存估算公式：2×层数×token数×d_model×2字节 |
| 🔥 **预训练** | 用海量通用文本（万亿Token）教模型通用语言知识 | 预训练语料/训练成本/训练时长 |
| **微调 SFT** | 用特定领域小数据(几千~几万条)继续教模型，适配特定任务 | Full全参 vs LoRA/QLoRA参数高效微调 |
| 🔥 **LoRA** | 微调只训A×B两个小矩阵(原权重冻住)，70B模型只加几百MB | 秩r参数：越大效果越好但文件越大 |
| 🔥 **Prompt工程** | 写对Prompt让LLM效果翻倍：Zero/Few-shot/CoT/结构化 | Few-shot示例/CoT思维链/自我一致性 |
| **LangChain / LlamaIndex** | LLM应用开发框架：把RAG/Agent/Tool的最佳实践封装好 | LCEL管道语法/Router/重排器 |
| **Context Window 上下文窗口** | LLM一次最多能"看到"多少Token：8K/32K/128K/1M | 成本+延迟随上下文线性+超线性增长 |
| 🔥 **幻觉 Hallucination** | LLM一本正经胡说八道，编造不存在的事实/引用 | 缓解方法：RAG+溯源+Self-Check+Groundness校验 |
| **Temperature 温度参数** | 控制生成随机性：0=确定不变，1=创意发散，>1胡编乱造 | 搜索/分类用0，创意写作用0.7~0.9 |
| **Token** | LLM处理文字的最小单位：中文1字≈1~2 Token，英文1词≈1.3 Token | 成本计费单位：1M Token价格从$0.1~$10不等 |

## 四、MLOps / AI工程化术语（平台岗高频）

| 术语 | 核心解释 | 对比传统开发 🔥 |
|------|---------|---------------|
| 🔥 **MLOps** | DevOps + ML：机器学习开发运维一体化 | DevOps管代码，MLOps管代码+模型+数据 |
| **MLflow** | 管理ML生命周期：实验追踪/模型注册/项目打包/部署 | 类似Maven仓库+Jenkins CI，但管理的是模型 |
| 🔥 **vLLM** | LLM高吞吐推理引擎，PagedAttention核心=显存利用率40%→95% | vLLM vs HF Transformers吞吐差10~20倍 |
| **PagedAttention** | 把KV Cache按固定Block分(OS虚拟内存思想)，支持连续批处理 | 连续批处理 vs 静态批处理区别 |
| **模型注册中心 Model Registry** | 管理模型版本：v1→v2→v3，Staging/Production/Archived | 类比Docker镜像仓库，但管的是模型权重 |
| **数据漂移 Data Drift** | 线上数据分布和训练时不一样，模型效果越来越差 | 类比传统代码"环境变了，代码跑不通" |
| **概念漂移 Concept Drift** | 输入分布没变，但X→Y的映射变了（如人们消费习惯因疫情改变） | 数据漂移 = 输入分布变了；概念漂移 = 规则变了 |
| **Feature Store 特征存储** | 统一管理特征：训练/推理用同一特征，避免训练-线上不一致 | 类比数据仓库，但特征是面向ML模型设计的 |
| **A/B Testing** | 新旧模型各分50%流量，线上真实对比指标 | 传统后端也有，但ML更依赖，离线指标≠线上效果 |
| **Shadow Mode 影子模式** | 新模型在后台跑但不生效，只记录预测 vs 实际结果对比 | 上线前最稳妥的验证方式，零风险 |
