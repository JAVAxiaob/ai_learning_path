## 🤔 技术选型决策树（遇到场景先看这个不迷路）

### 场景 1：移动端做物体识别
```
延迟要求 <100ms? ──Yes──▶ 端侧 TFLite / NCNN
用户隐私敏感?    ──Yes──▶ 端侧绝对不上传图片
设备经常离线?    ──Yes──▶ 端侧推理优先
模型精度要求极高? ──Yes──▶ 云端大模型兜底
结论：实时+隐私+离线 = 端侧；其他 = 灵活云端
```

### 场景 2：企业内部知识库问答
```
文档涉密不能出域?  ──Yes──▶ 本地 LLM + 本地向量库 Qdrant + 内网部署
预算有限?         ──Yes──▶ bge 本地 Embedding + 小模型 Rerank
技术栈 Java?      ──Yes──▶ Spring AI + LangChain4j + PostgreSQL pgvector
需要 Agent 工具调用? Yes ─▶ 加 ReAct 循环 + Function Calling
结论：Java 团队 + 数据敏感 → Spring Boot + Qdrant + 本地 Llama
```

### 场景 3：升级老的协同过滤推荐
```
现有系统规则老?       Yes ─▶ 渐进式升级不推翻：
① 先加一路 Embedding 向量召回（和现有召回并行）
② 加一个 XGBoost / DeepFM 排序模型精排
③ 最后加 Flink 实时用户行为特征流
结论：别 0-1 重构，先旁路实验 A/B，比老系统好再切流量
```

## 🧩 AI 开发 vs 传统开发：概念类比速查表（帮你秒懂）

| 你熟悉的传统开发概念 | AI 世界对应概念 | 一句话类比 |
|------------------|--------------|---------|
| 函数 f(x) = y | 模型推理 | 函数是 100% 确定性；模型是概率性的 P(y\|x) |
| 代码库 Java 文件 | 模型权重文件 .onnx/.bin | 代码是人写逻辑；权重是从数据里挖出来的规律 |
| JUnit 单元测试（断言） | 验证集 / 测试集评估 | 断言 assertEqual；AI 看 AUC/Recall/F1 指标 |
| 代码重构改 Bug | 模型重训练 / 更多更好数据 | 重构改代码逻辑；重训练换/补数据 + 调参 |
| Git 版本控制 | DVC / MLflow 模型版本 | Git 管代码；DVC 管 10GB 级大数据集和模型文件 |
| CI/CD 流水线 | MLOps 机器学习运维 | 代码自动发布；加上数据/模型/训练自动化闭环 |
| MySQL B+树索引 | 向量 ANN 索引 (HNSW) | B 树精确匹配；ANN 近似最近邻找最相似的向量 |
| 规则引擎 if-else 链 | 轻量 ML 模型 | 规则人写维护不过来；模型自动从数据学习 |
| A/B 测产品功能 | 模型 / Prompt A/B | 测按钮颜色；测不同 LLM 回答哪个用户点赞多 |
| Redis 缓存计算结果 | 推理语义缓存 | URL 作为 Key；用户问题 Embedding 相似度当 Key |
| 限流熔断 Hystrix | 推理服务限流 | 保护后端 DB；保护 GPU 不被打爆 OOM |
| application.yml 配置 | Prompt 模板 / 超参数 | 配置控制代码行为；Prompt 控制 LLM 行为风格 |
